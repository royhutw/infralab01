## 3. 已定案的架構決策

### 3.1 Cisco 交換器

- Access Port：`authentication order dot1x mab`、`port-control auto`、periodic＋`reauthenticate server`（NPS 端 86400 秒）、`tx-period 5`、`max-reauth-req 2`、`server-timeout 10`、`held-period 60`、`timer restart 30`、`authentication mac-move permit`。
- 失敗處置：`fail → VLAN 98`、`no-response → VLAN 90`、`server dead → VLAN 98`（Multi-Domain 另加 `authorize voice`）、`server alive → reinitialize`。NPS 不支援 CoA。
- **所有 Port（含 Multi-Domain `Gi0/2`）統一 `authentication violation replace`**：IP Phone 後方 PC 會不定期更換，需自動重新認證。代價是原裝置會被無預警斷線，已接受。
- Trunk Port **不能**跑 802.1X（Cisco 結構性限制）。Wi-Fi AP 的 Trunk Port（`Gi0/1`）＝純 Trunk＋Port-Security（`maximum 1`、**手動指定 MAC、不用 sticky、不加 `vlan` 限定**、`violation restrict`）。Allowed VLAN 不含 10。
- DHCP Snooping／DAI 範圍：`35,37,38,40,50,60,70-75,80,90,98`；靜態 IP 網段（10、20、21、25、30）不納入。Server Port（VM Host）採整段 trust，ARP ACL 方案因維護成本放棄，防護交給虛擬化層（vDS／NSX 等，**待與虛擬化團隊確認是否真的落實**）。骨幹 Trunk（`Gi0/0`、`Gi3/2`、`Gi3/3` 等）皆需 `ip dhcp snooping trust`＋`ip arp inspection trust`。
- STP：Core `priority 4096`（明確指定，不用 `root primary`）、`loopguard default`；Edge 不下 VLAN priority，`portfast bpduguard default`；Core↔Edge 下聯用 `guard root`，**Core-02↔Core-3 對等互連不加 `guard root`**（刻意）。正式環境為 10GbE×2 LACP（尚待改為 Port-channel）。
- CoPP：`class-map`／`policy-map`／`control-plane` 在 2960-X 實測可用（ICMP、ARP `match protocol arp`、DHCP、RADIUS、SSH，`class-default` 先 `exceed-action transmit` 觀察再收斂）。`mls qos copp protocol` 僅可補 STP／LLDP，不涵蓋 ICMP／RADIUS／SSH。
- 基線：停用 CDP、SSH v2、本機 AAA、`login block-for`、`PAW-MGMT-ACL`（只允許 `192.168.20.0/24`）、NTP／Syslog、errdisable recovery（arp-inspection／dhcp-rate-limit／bpduguard）。
- **IP PBX Port（Core `Gi3/1`）**：Access VLAN 38、portfast＋bpduguard、`ip arp inspection trust`、Port-Security `maximum 1` 綁 PBX 實體 MAC、`violation restrict`；PBX 內建 DHCP 不使用，DHCP 範圍已排除 PBX 靜態 IP。

### 3.2 NPS 政策（RADIUS1）

| 順序 | 政策 | 條件 → 結果 |
|---|---|---|
| 1 | `10-HQ-VLAN50-Machine Auth-EAP-TLS` | EAP＝Smart Card/憑證，`Domain Computers` → VLAN 50。NAS Port Type（**在 Constraints 頁籤**）同時勾 Ethernet＋Wireless 802.11 |
| 2 | 各部門 User Auth（60、70–75、80） | EAP＝憑證＋部門 AD 群組 → 對應 VLAN |
| 3–5 | MAB-Registration／MAB-Printers／MAB-IoT | Windows Groups＝對應 MAB 群組，PAP → VLAN 40／35／37 |
| 6 | `90-HQ-VLAN90-Guest_asteriskMAB` | `Calling-Station-Id` 正規表示式 `^[0-9a-fA-F]{12}$`（萬用兜底）→ VLAN 90 |
| 7 | Deny All | NPS 內建 |

- 每條 VLAN 指派皆為 `Tunnel-Type=VLAN`、`Tunnel-Medium-Type=802`、`Tunnel-Pvt-Group-ID=<VLAN>`。
- **已測試可正常運作**：VLAN 40 Registration MAB、VLAN 90 Guest。Machine／部門 User Auth 政策已建立，**使用者正在測試**；MAB-Printers 因 Lab 無實機尚未測。
- **PAW 不再有任何 NPS 政策**（`21-HQ-VLAN21-T0PAW-MachineAuth` 已廢棄）。
- **MAB 裝置治理＝「MAC 當作 AD 帳號」**：`OU=MAB-Devices`，群組 `MAB-Registration`／`MAB-Printers`／`MAB-AccessControl`(IoT)；帳號名稱與密碼＝裝置 MAC（**2960 預設送出小寫、無分隔符號**），密碼永不過期。NPS 政策設好後不再動，日常異動只在 AD 做。新機 Registration 帳號在確認改走 `dot1x` 後移除，Printer／IoT 帳號長期保留。
- **關鍵觀念**：NPS 是「Conditions 符合就押注到底」，驗證失敗**不會**往下一條。所以 User／Machine 政策必須有 EAP Type 條件，否則會攔截並拒絕 MAB 流量。精確條件排前、萬用排後。
- NPS 原生 PowerShell 只有 RADIUS Client 相關 Cmdlet（`New/Get/Set/Remove-NpsRadiusClient`）與 `Export/Import-NpsConfiguration`，**沒有**建立 Network Policy 的 Cmdlet。政策需 GUI 建立後匯出複製到 NPS-2。`New-NpsRadiusClient` 後需重啟服務 `IAS`。
- 帳號的「Network Access Permission」若設為 Deny，會蓋過 NPS 政策。

### 3.3 Windows 11 用戶端（802.1X）

- GPO：`Wired AutoConfig`（`dot3svc`）設為 Automatic（預設 Manual，是 802.1X 不動作的最常見原因）；`Wired Network (IEEE 802.3) Policies`。
- Authentication Mode＝**`User re-authentication`**（開機用電腦憑證、登入後換使用者憑證）；啟用 Single Sign-On＋「Perform immediately before User Logon」＋勾選「This network uses separate VLANs for machine and user authentication」；驗證伺服器憑證信任內部 Root CA。
- 已知風險（需實測）：登入時 VLAN 切換造成 IP 變動，可能中斷 GPO 背景處理／磁碟機對應；個別環境 Single Sign-On 反而讓 VLAN 切換不生效。
- 802.1X 的 EAPOL 是 Layer 2，無 IP 也能驗證；驗證通過後 Port 才放行 DHCP。
- **虛擬網卡（Proxmox／Hyper-V）的 EAPOL 支援不可靠**，使用者將抽出實體 PC 測試「開機 → VLAN 50 → 登入 → 部門 VLAN」。
- 新機（尚無憑證）流程：先落 VLAN 40（MAB-Registration）→ 加入網域 → `gpupdate`／重開機取得電腦憑證 → 重新接線走 EAP-TLS。**不能預先發臨時憑證**（範本的 Subject 由 AD 電腦物件的 `dNSHostName` 建構，未入網域前不存在）。

### 3.4 AD CS

- 範本（`04_create_templates.ps1` v13）：`EAP-TLS-Computer`（1 年）、`EAP-TLS-User`（2 年）、`EAP-TLS-NPS-Server`（2 年）；RSA 4096；Renewal＝有效期 **75%**（CA 強制上限，超過 MMC 會被擋）；自動核准＋Autoenrollment（`AEPolicy=7`，GPO 連結於網域根）。
- **範本權限強化**：User／NPS 範本停用繼承，只留 Domain Admins／Enterprise Admins（完全控制）＋ `Authenticated Users:GR`（**CA 本身需要 Read，否則 CA 看不到範本、`Element not found`**）＋指定 Enroll 對象（Domain Users／`NPS-Servers` 群組）。`SYSTEM` 的繼承 `GenericAll` 曾讓 CA 伺服器自己取得不該有的憑證。
- 已稽核本 CA 發布的 11 個內建範本：Enroll 範圍皆合理，未發現 ESC1 類風險（判斷法：Enroll 範圍廣＋可自訂 Subject＋Client Authentication EKU 三者同時成立才是風險）。
- 噪音現象：`Failed Requests` 內大量 `CERTSRV_E_TEMPLATE_DENIED`（非 NPS 電腦嘗試申請 NPS 範本）屬預期，不需處理；但若 `RADIUS1` 本身被拒才是異常。
- 稽核：兩層必須同時開（OS 進階稽核「Audit Certification Services」＋CA `AuditFilter=127`），詳見 `Set-ADCSAuditPolicy.ps1`。

### 3.5 特權存取（PAM）

- **PAW 為 VM，放在 2 台各自獨立的實體 Hyper-V Host**（Tier 0 一台、Tier 1 一台，皆由 Tier 0 管理員管理）。**靜態 VLAN**：Tier 0＝VLAN 20、Tier 1＝VLAN 21，皆接 Core。**不使用 PCI Passthrough／SR-IOV**（原因「為了 802.1X」已不存在）。
- Hyper-V 管理 IP 在 VLAN 10（獨立實體網卡）；PAW VM 用另一張網卡。VLAN 20 才能到 VLAN 10 管理 Port，VLAN 21（Tier 1）不行（pfSense 規則＋各主機本機防火牆來源限制）。
- Core 需 5 個 Access Port：兩台 Host 各 1 個管理（VLAN 10，綁 MAC）＋ 各 1 個 VM（VLAN 20／21，`maximum` 依台數、動態學習＋`aging inactivity`，**不綁固定 MAC**，因 VM 重建 MAC 會變）＋ 緊急實體 PAW 1 個（VLAN 20）。
- **緊急實體 PAW 保留（只有 Tier 0；Tier 1 不設，由 Tier 0 PAW 暫代）**：平時關機（或 Port shutdown），不走 802.1X，不依賴 RADIUS。**每月開機演練**（校時、域帳號登入、`gpresult`、Windows Update、S.M.A.R.T.，SOP 11.10）。
- **特權帳號只能登入對應 Tier 的 PAW**（`Allow log on locally`／`through RDS` 限定），以「空間隔離」取代做不到的 JIT／JEA。
- **Guacamole 堡壘機 Tier 0／Tier 1 各一架**（避免軟體、資料庫、Session 錄影共用）；每帳號只獲得單一 Tier 的 PAW 存取；所有帳號使用公司配發、**Air-gapped** 手機上的 TOTP（Authenticator 類 App）。此 MFA 設計實質接近硬體金鑰，攻破需要實體滲透。
- 兩台堡壘機各自放哪個 VLAN 尚未定案（原為單台放 VLAN 25）。

### 3.6 其他

- **Aruba IAP-305**：管理介面 VLAN 34；企業 SSID＝WPA3-Enterprise＋802.1X，使用者 VLAN 由 NPS 動態指派；訪客 SSID＝WPA3-Personal 過渡模式，VLAN 90，開 Client Isolation。AP 的 Virtual Controller 需固定 IP 並登記為 RADIUS Client。
- Core 與 pfSense 的 Gateway 容錯：Core 純 L2，若要做 Gateway 層高可用應評估 pfSense CARP，不是在 Switch 上做 HSRP。

## 5. 重要經驗教訓（請在新討論串沿用）

**憑證範本旗標**
- `msPKI-Certificate-Name-Flag`：`0x00000001`＝`ENROLLEE_SUPPLIES_SUBJECT`（危險，不是「要求 CN」）；User 範本用 `0x42000000`；Computer／伺服器範本用 `0x18000000`。
- `flags` 的 `CT_FLAG_MACHINE_TYPE (0x40)` 只能給電腦／伺服器範本；User 範本若含它，CA 會改用電腦物件建構 Subject（曾導致 User 憑證發給電腦）。
- Renewal 不得超過有效期的 75%。

**ACL／dsacls**
- `[ADSI]`＋`CommitChanges()`、`Get-Acl/Set-Acl`、`DirectoryEntry` 都無法可靠寫入「停用繼承」；改用 `dsacls`：先 `/P:Y` 再 `/R`；Extended Right 用顯示名稱 `CA;Enroll`／`CA;AutoEnrollment`（不接受 GUID 字串）；每次呼叫只帶一個 `/G`。
- 停用繼承後務必保留 `Authenticated Users:GR`。

**驗證習慣**
- 不要相信腳本印出的 `[OK]`；檢查結束碼，並在**全新 PowerShell 視窗**讀回確認。
- 加入 AD 群組後，電腦要重開機（或清 Kerberos 票證）才有新權限（RADIUS1 加入 `NPS-Servers` 時親身遇到）。
- 範本物件被刪除重建後，CA 可能有快取，`Restart-Service CertSvc`。
- 驗證邏輯本身也會出錯（曾因「先四捨五入再算比例」誤判）。

**其他**
- Windows PowerShell 5.1 與 PowerShell 7 行為不同；我在沙盒用 PS 7.4 測試，5.1 無法實測。
- 我曾在 SOP 編輯時意外刪除「情境 D」，已補回；日後大幅編輯 SOP 後請檢查章節完整性。
- 缺空白的寫法（`-Target$x`）會讓參數值遺失，審核腳本時要特別注意。
